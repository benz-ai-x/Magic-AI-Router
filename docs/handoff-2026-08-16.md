## 本会话破案：DeepSeek 8/15 起 usage 全零

- **现象**：usage.jsonl 中 DeepSeek 行 8/15 76%、8/16 100% 记账全零（`status=200, err=None, 四项计数全 0`）；GLM/KIMI 不受影响。
- **排查**：黑盒排除 SSE 格式/压缩/二进制变更/beta 头/`[1M]` 后缀/请求形状（162k token 均正常提取）；白盒 chunk-tee 抓到真实 Claude Code 上游 SSE 完全正常（`input_tokens: 49383` 就在 `message_start` 里）。
- **根因**：**`stream:false` 非流式请求**。上游响应是单个 JSON 文档（usage 在顶层），`UsageExtractor` 只扫 SSE `data:` 行 → 喂 JSON 解析出零。8/15 起 CC 对 sonnet 档（= DeepSeek 路由）开始发非流式请求，所以只有 DeepSeek 中招。
- **修复**（#49，TDD 先红后绿）：`UsageExtractor(json_mode=True)` 缓冲 JSON 体完整后取顶层 usage；`forward_request` 按上游 content-type 切模式，SSE 路径零回归。端到端验证：真实 DeepSeek `stream:false` 记账 `in=85 out=19`（修复前同请求全零）。
- **调试现场已清**：临时 tee 代码已还原、调试网关已杀、`/tmp/suanpan-debug.yaml`（含真 key）已删。

## 缓存架构定案（详见 ADR-004）

调研依据：deepseek-harness（DeepSeek 官方 agent harness）。**两个缓存家族**：

- **Anthropic 显式**（GLM/KIMI 的 Anthropic 端点）：需 `cache_control` 标记 + 报写指标（`cache_creation`）→ 用 #48 的 `anthropic_native` 保标记。
- **DeepSeek 自动前缀**：服务端全自动，无需任何标记，**不报写指标**，命中报告于 `cache_read_input_tokens` → 不需要 `anthropic_native`，#49 后非流式路径也可观测。

**前缀稳定性契约**：`normalize_body` 必须保持确定性——归一化形状变更 = 一次性打冷所有上游缓存；禁止运行时可变形状开关；`anthropic_native` 属部署级配置不反复切。JSON 键序/空白不影响 tokenization，无需字节级一致。
